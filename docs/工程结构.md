# 工程结构

ScreenGuard 的应用代码、测试、工具及运行数据分别存放。相对路径均以项目根目录为基准。

```text
ScreenGuard/
├─ src/task2_video_panel/
│  ├─ framework_part/app/
│  │  ├─ core/                配置、数据库和迁移
│  │  ├─ routers/             HTTP 接口
│  │  ├─ services/            采集、识别、事件、审核和运维
│  │  └─ static/              前端页面、样式和脚本
│  ├─ recognition_part/       训练、评测和数据工具
│  ├─ sample_media/           合成演示视频
│  ├─ configs/                外围集成示例
│  └─ manage.py               服务、账号和数据管理命令
├─ tests/                     回归与验收工具
├─ scripts/windows/           Windows 启停与配置加载
├─ deploy/                    企业守护和 Linux 服务模板
├─ config/                    配置示例；本机配置不提交
├─ docs/                      使用与开发文档
├─ windows_preview/           默认运行数据、日志和进程状态
├─ artifacts/                 测试和构建输出
└─ *.bat                      Windows 快捷入口
```

## 服务入口

`scripts/serve_windows.py` 启动本机工作台。根目录 `start_windows.bat`、`stop_windows.bat` 调用 `scripts/windows` 中的实现。企业账号模式由 `manage.py` 提供，Windows 进程守护位于 `deploy/supervise.py`，Linux 服务模板位于 `deploy/screen-guard.service.example`。

`framework_part/app/main.py` 创建 HTTP 应用及后台维护任务。视频采集和有时限的 ONNX 推理使用子进程，采集管理、事件聚合和自动辅助审核保留独立状态。前端通过工作台 API 访问数据。

## 配置与运行数据

Windows 启动器读取 `config/runtime_config.json`，同名进程环境变量优先。兼容根目录 `runtime_config.json` 作为后备配置。Python、模型和服务程序路径可按安装环境修改；未填写本地模型路径时仍可启动基础工作台。

`data_dir` 保存数据库、证据、上传素材和导入模型，`state_dir` 保存日志、缓存及进程状态。Windows 启动器要求这两类路径位于项目内；Linux 的 `manage.py --data-dir` 支持单独设置服务数据目录。默认位置为 `windows_preview/runtime/data` 与 `windows_preview`。

## 测试与模型工具

`tests/run_tests.py` 分进程运行各测试套件。模拟摄像头与真实本地模型验收使用单独命令，详见 [测试入口](../tests/README.md)。测试产物集中保存到 `artifacts`。

训练和离线评测工具位于 `recognition_part`，生成文件默认保存到 `artifacts/training` 或 `artifacts/evaluation`。数据清单、划分和模型评估要求见 [工作台与模型工具](WORKBENCH.md) 和 [数据集规范](DATASET.md)。

## 版本控制边界

提交源码、测试、配置示例和文档。运行数据库、真实证据、上传素材、模型权重、日志、API 密钥和本机配置由运行环境管理，不作为源码提交。迁移或升级前使用工作台备份功能保存运行数据，并在目标环境验证恢复结果。
