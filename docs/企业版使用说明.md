# 企业工作台使用说明

本说明介绍账号权限、审核处置、通知、备份和部署。首次安装与基础配置见 [使用说明](使用说明.md)。命令均从项目根目录执行。

## 功能入口

- **设置**：每日复核时间、60 分钟审核预算、单条预计审核时间、每路每日抽检上限、7 天留存、容量上限、重启恢复和 Webhook 静默时间。
- **人工复核**：优先告警、定时批次、即将到期筛选。采集中的事件须先“固定当前片段后审核”；继续出现的画面另建待审片段。审核历史记录操作者、内容版本、媒体时间范围及证据摘要。
- **运行与通知**：审核积压、存储分项、站内通知签收、Webhook 发送记录、视频源管理、账号管理、操作记录、完整备份和 CSV 报表。
- **素材与模型**：提供本地与云端模型连接配置。审核员可在事件详情请求模型建议；连接设置和模型变更由管理员操作。

需要使用本地 Qwen 图片接口时，先运行 `start_local_model_vision.bat`，等待模型加载完成，再在工作台测试本地连接；结束时使用 `stop_local_model.bat`。大模型接口的图片建议与主采集分类器是两个配置入口，新安装默认使用 `demo-rules` 演示规则。

通知签收只表示已看到通知，不能代替事件审核。确认风险的证据和管理员手动保留的证据不会随疑似样本到期清理。缺少可查看证据时，只能提交“不确定”，不能直接认定正常或确认风险。

## 持续监控与处置

监控卡片的“设备与自动审核设置”可以测试画面、标定区域、覆盖本路采样/模型/阈值、配置运行时段，并启用本地自动辅助审核。云端补充需逐路选连接并允许发送，默认关闭。先加载图片模型，再开始采集，避免模型冷启动同时争用资源。

自动请求只处理固定后的疑似片段，受次数、间隔、去重及排队有效期控制；失败、取消和超时仍留待人工审核。总览可查看自动队列和各项维护任务。采集新鲜不代表识别成功，页面分别显示采集时间、识别时间和处理延迟；后台超过 15 秒未更新总览会出现过时提示。

确认风险后进入“待处置 / 处理中 / 已解决”流程，可填写负责人及处置说明。审核员有处置权限，历史包含操作者和时间。通知签收、风险审核、现场处置各自记录；修改已确认的风险标签会重新打开已有处置。

升级运行库前先停止旧服务。升级前生成 SQLite 快照，完整恢复仍使用下述运行备份。恢复备份默认停止视频源、关闭自动模型调用、取消旧队列并暂停历史通知投递。

## Windows 企业账号模式

1. 先运行 `stop_windows.bat` 停止本机演示。
2. 运行 `create_enterprise_admin.bat`，在终端输入管理员账号和至少 12 字符的密码；密码不回显。
3. 运行 `start_enterprise.bat`，保持该终端运行，浏览器打开 http://127.0.0.1:8765。
4. 管理员登录后，在“运行与通知 → 账号”创建审核员。审核员可以审核和签收，不能修改源、模型、设置、账号和 Webhook，也不能读取或删除完整备份。

企业启动入口带进程守护：异常退出后退避重启，连续五次短时失败会停止并提示检查。退出该终端中的服务使用 **Ctrl+C**。`stop_windows.bat` 用于本机演示入口。

审核会话空闲 30 分钟或满 24 小时后需要重新登录。后台轮询不延长空闲时间；停用账号或重置密码会注销它的会话。同一数据目录只能运行一个服务。

管理员需要重置密码时，在项目终端执行以下 CMD 命令：

```bat
".venv\Scripts\python.exe" -X utf8 -B "src\task2_video_panel\manage.py" --data-dir "windows_preview\runtime\data" reset-password 账号名
```

## 通用 Webhook

未配置外部地址时，通知只保存在站内。在“运行与通知 → 通用 Webhook”填写 HTTPS 地址并启用即可；地址留空表示保留原值。

Windows 保存的地址使用当前用户的 DPAPI 加密。Linux 使用环境变量 `SCREEN_GUARD_WEBHOOK_URL`。如果接收端要求签名，可在服务环境中配置 `SCREEN_GUARD_WEBHOOK_SIGNING_KEY`；发送头为 `X-ScreenGuard-Signature: sha256=<HMAC-SHA256>`，签名对象是原始 JSON 请求字节。

JSON 包含 `id、kind、title、event_id、source_id、created_at`，不包含图片或审核备注。接收端返回 2xx 表示成功，并应按 `id` 去重。每条通知最多自动尝试三次；失败后可人工重新投递。地址配置变化会阻止旧任务直接投递到新地址，需要人工重新提交。具体企业平台若采用不同消息格式，需要在接收端转换或另加适配器。

静默时间只延后汇总和恢复通知的 Webhook 投递；风险告警、设备和存储异常继续排队发送。站内通知一直保留。

## 备份和恢复

管理员在“运行与通知 → 备份与恢复”创建和下载备份。备份包含运行数据库、账号、事件、注册证据、上传视频、已导入 ONNX 模型和旧快照；不包含项目代码及数据目录外的 GGUF/mmproj 文件。

先固定数据库和文件引用，再压缩，压缩阶段允许继续写入新采集数据。备份最多保留三份；下载确认后可以移除旧备份。备份只允许管理员读取，登录会话不随备份导出。

恢复前校验全部文件摘要，恢复目录必须不存在；恢复后视频源停止，通知不会自动重投。下面是 CMD 恢复演练命令，将“备份文件名”换成实际 ZIP 名称，先在工程根目录创建 `artifacts`：

```bat
".venv\Scripts\python.exe" -X utf8 -B "src\task2_video_panel\manage.py" --data-dir "windows_preview\runtime\data" restore "windows_preview\runtime\data\backups\备份文件名.zip" "artifacts\restore_drill"
```

离线 `backup` 命令要求先停止服务；在线备份使用工作台入口。完整备份含账号摘要和流地址，应按企业运行数据保管。

## Linux 迁移准备

`deploy/screen-guard.service.example` 提供 systemd 模板，需按部署环境安装和注册。将工程迁移到选定位置，使用 Python 3.11 和 `src/task2_video_panel/framework_part/requirements.txt` 配置服务环境，再恢复数据。完整回归另需安装 `requirements-dev.txt`。Windows 验证所用版本记录在 `deploy/requirements-windows-validated.txt`，Linux 安装包和依赖尚未验证。

服务保持回环监听；远程访问通过 HTTPS 反向代理，配置 `SCREEN_GUARD_ALLOWED_HOSTS` 为实际域名。模板中的路径、域名、运行用户和环境文件须按部署环境修改。

迁移时重新填写本地 GGUF/mmproj 路径。Windows DPAPI 保存的 API 密钥及 Webhook 地址不能直接在 Linux 解密：清除旧保存值，改用 Linux 服务环境变量。复核并手动开始视频源后，后续服务重启才按“期望运行状态”恢复采集。
